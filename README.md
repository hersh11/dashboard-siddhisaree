# Siddhi Sarees — Order Analytics Dashboard

An internal order management and business analytics dashboard for a bespoke ethnic-wear business — built to turn scattered order notes, staff assignments, and production updates into a single management-ready view.

## Overview

Siddhi Sarees is a made-to-order ethnic-wear business where every order moves through eight stages — enquiry, design, production, quality check, packaging, shipping, and delivery — each touched by a different employee. This dashboard consolidates that lifecycle, plus customer and sales data, into one operational view: what's selling, where orders are stuck, and who's handling what.

The underlying dataset (`siddhi_sarees_dataset.xlsx`) is synthetic — generated by the Python scripts in the parent project to model a realistic six-month order volume — so the dashboard can be explored end-to-end without exposing real customer data.

## Features

**Analytics**
- Live KPI row — total orders, delivered revenue, average order value, repeat-customer share — with animated count-up on update
- Monthly revenue & order-volume trend, order status mix, revenue by product category, channel contribution
- Stage-completion funnel and average time-in-stage across the 8-step production lifecycle
- Domestic vs. NRI demand split, plus top colors / fabrics / work types

**Filtering & Search**
- Date range, status, category, channel, and priority filters — every chart, KPI, and table updates live
- Independent search on the team table and the order register

**Team & Order Management**
- Team performance table (assignments, completions, order value handled) — sortable on every column
- Live order register, sortable and paginated, with one-click CSV export of the current filtered/sorted view

**Polish**
- Dark mode with persisted preference
- Scroll-triggered reveal animations and hover states, all respecting `prefers-reduced-motion`
- Fully responsive down to mobile, keyboard-accessible, WCAG AA color contrast

## Tech Stack

| Layer | Choice | Why |
|---|---|---|
| Structure | Semantic HTML5 | No JSX/templating needed for a single-page dashboard |
| Styling | Hand-written CSS (custom properties, Grid/Flexbox) | Full control over the light/dark theme system, zero build step |
| Logic | Vanilla JavaScript (ES2020+) | Filtering, sorting, CSV export, and chart orchestration without framework overhead |
| Charts | [Chart.js](https://www.chartjs.org/) (vendored locally) | Works fully offline, no CDN dependency |
| Data pipeline | Python (`data_generation/`: three seeded generators + `build_workbook.py`) | Produces the Excel workbook this dashboard reads |
| Local server | Node.js (`server.js`, ~40 lines, no dependencies) | Serves static files with correct MIME types — `fetch()` from `file://` doesn't work for local JSON/data |

## Getting Started

**Prerequisites:** [Node.js](https://nodejs.org/) (any recent LTS version). No `npm install` needed — the server has no dependencies.

```bash
git clone https://github.com/hersh11/dashboard-siddhisaree.git
cd dashboard-siddhisaree
node server.js
```

Then open **http://127.0.0.1:8766/index.html** in your browser.

> The data ships pre-built. To rebuild the workbook: `pip install pandas openpyxl`, then `python data_generation/build_workbook.py`. The generators are seeded, so the rebuilt data matches the committed workbook row for row (the Summary sheet holds formulas that Excel computes on open). `dashboard-data.js` is the same data in a browser-readable form.

## Testing

`tests/run_tests.py` is a Playwright script (Python, headless Chromium) with 48 checks across nine areas: data integrity, KPI cards, filters, charts, tables and search, CSV export, theme, keyboard and screen-reader access, and responsive layout at 1440, 1024 and 390 px. Every expected value was worked out from the workbook in Python, not read off the screen. The full plan, results and defect write-ups are in [`tests/TEST_REPORT.md`](tests/TEST_REPORT.md).

Latest run: **45 passed, 2 failed, 1 diagnostic.**

- **D-01, fixed.** The "average time in stage" chart showed zero for every stage. Each stage row stores one timestamp, not a span, so the time an order spends at a stage is the gap to its next stage. `app.js` now measures that gap. Production turns out to be where orders wait longest (13.8 days on average).
- **D-02, open.** The two display fonts load from Google Fonts, so the page is not fully offline. Both failures (TC-A1, TC-A7) come from this in a run with no internet access. With the font servers unreachable the dashboard still renders in full (TC-A8). Self-hosting the fonts is first on the roadmap.

Run the suite:

```bash
pip install -r tests/requirements.txt
python -m playwright install chromium
node server.js                 # terminal 1
python tests/run_tests.py      # terminal 2
```

## Data Model

The dashboard reads from `siddhi_sarees_dataset.xlsx`, which has five sheets:

| Sheet | Contents |
|---|---|
| `Orders` | One row per order — product, pricing, customer, channel, status, current stage |
| `OrderStages` | One row per order-stage — the full 8-step lifecycle, assigned employee, timestamps, notes |
| `Customers` | Location, customer type, acquisition source, lifetime spend |
| `Employees` | Name, role, department |
| `Summary` | High-level precomputed business metrics |

## Design System

- **Palette** — deep maroon, teal, and gold, chosen to reflect the brand's textile/ethnic-wear identity, on a warm cream (light) / warm charcoal (dark) surface
- **Type** — Playfair Display for headings and KPI figures, Inter for body copy and dense data, with a system-serif fallback if the web font can't load
- **Motion** — CSS-only: scroll-triggered reveal, hover-lift on cards, animated KPI count-up — all gated behind `prefers-reduced-motion`
